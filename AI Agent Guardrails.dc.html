01 · Why It Matters02 / 18

An LLM agent is no longer a chatbot.

It plans, calls tools, reads untrusted data from the web and inboxes, writes to databases, holds memory across sessions, and coordinates with other agents. Each capability expands the attack surface.

Guardrails are the runtime control plane — they decide, at every step, whether what the agent is about to read, say, or do is allowed.

NEW CAPABILITIES, NEW EXPOSURE
→Plans multi-step tasks autonomously
→Calls tools with real credentials
→Reads untrusted web, email, documents
→Persists memory across sessions
→Coordinates with other agents

02 · The Control Model07 / 18

Two principles behind every defense

PRINCIPLE 01

Defense-in-depth, not a single point of trust

Anthropic's "Swiss-cheese" model: each layer has holes, but they don't line up. No single classifier is robust on its own.

30% → 0% attack success rate when specialized detectors are stacked
PRINCIPLE 02

Treat all external content as untrusted

The agent's reasoning context is a security boundary. Anything crossing it from outside must be labeled, sanitized, or sandboxed.

03 · Key Defenses10 / 18

Tool & action rails

highest blast radius
LEAST PRIVILEGE

OAuth 2.1 + DCR, per-request downscoped tokens, shortest TTL. Agent personas & capability profiles. MiniScope — 1–6% overhead.

RUNTIME ENFORCEMENT

AgentSpec — triggers/predicates, blocks >90% unsafe code execution. OPA / Rego deny-by-default at every tool call.

SANDBOXING

gVisor, Firecracker, Kata microVMs. Ephemeral sandboxes (E2B, Modal, Anthropic) — fresh state, scoped egress, time-bounded creds.

HUMAN-IN-THE-LOOP

Risk-tiered routing: read-only runs free; write / irreversible actions gate on approve/reject. Confidence-based escalation preserves throughput.

03 · Key Defenses11 / 18

Retrieval & memory rails

RAG poisoning · MINJA
WRITE-PATH HYGIENE

Moderate everything before indexing. Source provenance & signing. Author / tenant isolation. Semantic gate on memory writes.

RETRIEVAL-TIME

NeMo retrieval rails reject / rewrite chunks. Activation-based detectors (RevPRAG). Isolate-then-aggregate. Source-aware citation.

MEMORY ARCHITECTURE

Separate episodic / semantic / procedural with different write policies. Bounded horizon. Write requires inspectable reasoning step.

>95%MINJA memory-injection success — by a regular user, no system access
Memory poisoning is the silent failure.Unlike a jailbreak, it triggers no alert today and ruins behavior next quarter. Moderate writes, not just reads.
03 · Key Defenses12 / 18

Information flow control

CaMeL · FIDES · dual-LLM

Don't detect bad content — make it structurally impossible for untrusted data to influence sensitive operations. Taint tracking for agents.

P-LLM · PRIVILEGED

Sees only the trusted user query. Plans the program and calls tools. Never sees untrusted data.

×
Q-LLM · QUARANTINED

Sees untrusted text (email, web). Returns only typed, structured objects. Cannot call tools.

×
CAPABILITY INTERPRETER

Every value carries provenance metadata. Policy decides whether a tool may run with values of that origin.

Net effect: even a fully jailbroken Q-LLM can't reach a forbidden sink — converts a probabilistic problem into a structural one. Cost: complexity + reduced utility.

The implementation roadmap

WEEK 1–2 · FOUNDATION
  • One PI / jailbreak classifier in front of every call
  • Schema validation on all tool args & outputs
  • HITL on irreversible tools (denylist)
  • Managed content classifier on outputs
  • Log every rail decision (OpenTelemetry)
WEEK 3–6 · LAYER IN
  • NeMo (or equivalent) dialog + execution rails
  • Spotlighting on every retrieved / tool span
  • Policy-engine authz, deny-by-default tokens
  • Retrieval rails & write-time moderation
  • Eval harness: AgentDojo + domain set
HIGH-STAKES · INVEST
  • Dual-LLM / CaMeL information flow control
  • Custom classifiers from your written policy
  • Continuous + human red-teaming in CI
  • Adaptive-attack evaluations
  • Audit & governance plumbing
